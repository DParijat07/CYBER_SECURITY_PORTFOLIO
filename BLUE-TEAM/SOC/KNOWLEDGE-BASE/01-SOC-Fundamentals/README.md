# 🧠 What is a SOC?

A **Security Operations Center (SOC)** is a function responsible for continuously monitoring, detecting, investigating and responding to cybersecurity threats affecting an organization's environment.

A SOC typically combines:

```text
People
  +
Processes
  +
Technology
  ↓
Security Operations
```

The ultimate objective is:

> **Detect threats early, investigate them accurately, respond effectively, and reduce organizational risk.**

---

# 🏢 Why Organizations Need a SOC

* Endpoints
* Servers
* Network devices
* Firewalls
* Applications

A SOC provides a structured capability to:

# 📜 Events, Alerts and Incidents

These terms must not be treated as interchangeable.

## Event

An event is an observable activity.

Example:

```text
User failed authentication.
```

An event is not automatically malicious.

---

## Alert

An alert is generated when security logic identifies activity that may require investigation.

Example:

```text
50 failed logins detected from one source IP.
```

---

## Incident

An incident is a confirmed or sufficiently suspected security event requiring a security response.

Example:

```text
Compromised account confirmed through
successful authentication after password spraying.
```

### Relationship

```text
Event
  ↓
Detection Logic
  ↓
Alert
  ↓
Investigation
  ↓
Incident
```

# 🔎 IOC — Indicator of Compromise

An **IOC** is an observable artifact associated with potentially malicious activity.

Examples:

* IP address
* Domain
* URL
* File hash
* Malicious filename
* Email address
* Registry key
* Suspicious process

Example:

```text
Hash → known malware
IP → malicious infrastructure
Domain → phishing infrastructure
```

IOCs provide useful evidence but must be interpreted in context.

---

# 🎯 IOA — Indicator of Attack

An IOA focuses more on **suspicious behavior or attack activity** than on a specific artifact.

Examples:

* Repeated authentication attempts
* Suspicious PowerShell execution
* Credential dumping behavior
* Unusual lateral movement
* Abnormal privilege escalation

---

# 🧠 TTP — Tactics, Techniques and Procedures

TTPs describe adversary behavior.

```text
Tactic
  ↓
Technique
  ↓
Procedure
```

Example:

```text
Tactic:
Credential Access

        ↓

Technique:
Credential Dumping

        ↓

Procedure:
Specific method/tool used to obtain credentials
```

TTP-based detection is often more resilient than relying only on static IOCs.

# 🚨 Threat Detection Fundamentals

Detection is the process of identifying potentially malicious activity.

Detection can be based on:

### Signature

Known malicious pattern.

### Rule

Predefined logical condition.

### Anomaly

Activity deviates from expected behavior.

### Behavior

Suspicious sequence of actions.

### Intelligence

Known threat information.

---

# 🧩 Detection Example

Consider repeated failed logins:

```text
User: admin
Source IP: 10.10.10.50

09:00 → Failed
09:01 → Failed
09:02 → Failed
09:03 → Failed
...
```

A detection rule may identify:

```text
Multiple authentication failures
within a short time window
```

This produces:

```text
Event
 ↓
Correlation Rule
 ↓
Alert
```

The analyst then determines whether it is:

* Normal user behavior
* Misconfiguration
* Brute-force attempt
* Password spraying
* Compromised account activity

---

# ⚠️ False Positive vs True Positive

## False Positive

The security system generates an alert, but the activity is legitimate.

Example:

```text
Administrator performs
multiple failed login attempts
during troubleshooting.
```

## True Positive

The alert represents genuine malicious or unauthorized activity.

Example:

```text
External source performs
repeated authentication attempts
against multiple accounts.
```

SOC analysts must learn to distinguish between them.

# 📊 Severity & Prioritization

Not every alert deserves the same response priority.

Typical categories:

```text
Critical
High
Medium
Low
Informational
```

Severity may depend on:

* Asset criticality
* Threat confidence
* User privilege
* Attack stage
* Business impact
* Exploitability
* Scope
* Evidence

A high-volume alert is not necessarily a high-risk incident.

# 🔐 SOC Analyst Mindset

A strong SOC analyst should avoid immediately assuming:

> "This is an attack."

Instead, ask:

```text
What happened?
       ↓
When did it happen?
       ↓
Which system?
       ↓
Which user?
       ↓
What process?
       ↓
What network connection?
       ↓
Is it expected?
       ↓
What evidence supports the conclusion?
       ↓
What is the potential impact?
       ↓
What should happen next?
```

The analyst's job is to make **evidence-based decisions**.
