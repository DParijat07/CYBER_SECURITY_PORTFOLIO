# Application Monitoring

> **Blue Team → SOC → Security Monitoring → Application Monitoring**

Application monitoring provides visibility into how applications behave, communicate, authenticate users, process requests, and interact with databases, APIs, operating systems, and external services.

For a SOC analyst, application telemetry is important because many attacks become visible first at the application layer.

A useful mental model is:

```text
User
 ↓
Application
 ↓
API
 ↓
Database
 ↓
External Services
```

Security monitoring should provide visibility across this entire chain.

# 2. Why Application Monitoring Matters

Network monitoring tells you:

```text
Who communicated with whom?
```

Endpoint monitoring tells you:

```text
What happened on the machine?
```

Application monitoring tells you:

```text
What did the user actually do inside the application?
```

For example:

```text
User
 ↓
Login
 ↓
Access Account
 ↓
Request API
 ↓
Modify Data
```

This context is extremely valuable during an investigation.

# 7. HTTP Methods

Common HTTP methods include:

```text
GET
POST
PUT
PATCH
DELETE
HEAD
OPTIONS
```

Security monitoring should understand expected application behavior.

For example:

```text
GET /profile
```

may be normal.

But:

```text
DELETE /admin/users/25
```

requires appropriate authorization and should be monitored.

---

# 8. HTTP Status Codes

Important status codes:

```text
2xx → Success
3xx → Redirect
4xx → Client Error
5xx → Server Error
```

Examples:

```text
200 → OK
201 → Created
301 → Redirect
400 → Bad Request
401 → Unauthorized
403 → Forbidden
404 → Not Found
429 → Too Many Requests
500 → Internal Server Error
```

Large numbers of unusual 4xx or 5xx responses may indicate attacks, application problems, or misconfiguration.

# 17. SQL Injection Monitoring

Potential SQL injection indicators include suspicious input patterns.

Example concept:

```text
/api/user?id=' OR '1'='1
```

or other malformed database-oriented input.

SOC monitoring may detect:

```text
Repeated Suspicious Requests
+
Database Errors
+
Unusual Parameters
```

A single string should not automatically be considered a confirmed attack.

# 61. Key Takeaways

```text
1. Application monitoring provides visibility into user actions and application behavior.

2. Authentication logs are critical for detecting credential attacks.

3. Authorization monitoring helps identify privilege and access-control abuse.

4. API monitoring is increasingly important because modern applications are API-driven.

5. HTTP status codes provide useful behavioral context.

6. WAF telemetry can identify application-layer attack patterns.

7. Application errors can reveal probing, attacks, or misconfiguration.

8. Session and token monitoring can help identify account and session abuse.

9. Database telemetry strengthens application investigations.

10. Application-layer DoS can occur without traditional network flooding.

11. Data exports should be monitored and baselined.

12. Application logs should contain enough context to reconstruct user activity.

13. Logs must not expose sensitive secrets.

14. Application telemetry becomes significantly more valuable when correlated with WAF, endpoint, identity, network, and database telemetry.

15. A SOC analyst should learn to reconstruct an application attack as a timeline.
```
