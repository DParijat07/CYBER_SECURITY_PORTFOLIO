# Security Monitoring Concepts

> **Blue Team → SOC → Security Monitoring**

Security monitoring is the continuous observation and analysis of activity across an organization's systems, endpoints, networks, applications, identities, and cloud infrastructure to identify suspicious behavior, security incidents, and potential threats.

For a SOC analyst, security monitoring is the bridge between **visibility** and **detection**.

```text
Environment
     ↓
Security Events
     ↓
Telemetry / Logs
     ↓
Collection
     ↓
Normalization
     ↓
Correlation
     ↓
Detection
     ↓
Alert
     ↓
Investigation
     ↓
Response
```

# 15. Log Aggregation

Organizations usually have logs distributed across many systems.

Without aggregation:

```text
Windows ──→ Logs
Linux ─────→ Logs

```

Analysts would need to investigate each source independently.

With centralized aggregation:

```text
Windows ──┐

Firewall ─┤
Cloud ────┤
DNS ──────┤
           ↓
      Central Platform
           ↓
          SIEM
           ↓
       SOC Analyst
```

This enables centralized visibility.

# 17. Monitoring vs Detection

These concepts should not be confused.

### Monitoring

Answers:

> **What is happening?**

Example:

```text
PowerShell executed.
```

### Detection

Answers:

> **Does this behavior match a suspicious pattern?**

Example:

```text
PowerShell
+
Encoded Command
+
Suspicious Parent Process
+
External Network Connection
```

Therefore:

```text
Monitoring = Visibility

Detection = Identification of potentially malicious behavior
```

---

# 18. Monitoring vs Alerting

Not every event should generate an alert.

Example:

```text
Normal Login
```

may simply be monitored.

But:

```text
100 Failed Logins
+
Successful Login
+
Privileged Account
```

may generate an alert.

Therefore:

```text
Events
   ↓
Monitoring
   ↓
Detection Logic
   ↓
Alert
```

Good monitoring does not mean generating as many alerts as possible.

# 22. False Positive

A false positive occurs when a detection identifies legitimate activity as suspicious.

Example:

```text
PowerShell Alert
      ↓
Investigation
      ↓
Approved IT Script
      ↓
Legitimate Activity
```

The correct response is not simply to disable the detection.

Instead:

```text
Investigate
   ↓
Understand Why It Triggered
   ↓
Tune Detection
   ↓
Reduce Future Noise
```

---

# 23. False Negative

A false negative occurs when malicious activity is not detected.

Example:

```text
Malicious Activity
      ↓
No Detection
      ↓
No Alert
```

False negatives are dangerous because they create security blind spots.

A mature SOC continuously works to reduce both:

```text
False Positives
False Negatives
```

---

# 24. Alert Fatigue

Alert fatigue occurs when analysts receive excessive alerts, especially low-value alerts.

Example:

```text
10,000 Alerts
      ↓
9,500 Low Value
      ↓
500 Relevant
```

High alert volume can cause:

```text
Delayed Investigation
Missed Alerts
Analyst Burnout
Poor Prioritization
```

Therefore detection engineering should focus on:

```text
Quality
+
Context
+
Prioritization
```

rather than raw alert volume.

# 26. Correlation

Correlation connects multiple events.

Example:

```text
Failed Login
     ↓
Successful Login
     ↓
PowerShell
     ↓
Network Connection
     ↓
File Creation
```

Each event alone may appear harmless.

Together they may represent a potential attack chain.

Correlation is one of the major strengths of SIEM platforms.

# 34. Security Monitoring Investigation Model

For every alert ask:

```text
WHO?
WHAT?
WHEN?
WHERE?
WHY?
HOW?
```

Then expand:

```text
What happened before?
What happened after?
What else is related?
Is this expected?
What is the impact?
```

Finally:

```text
What should happen next?
```
